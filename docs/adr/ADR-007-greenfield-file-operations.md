# ADR-007: Greenfield File Operations (fs_list and fs_write)

## Status
Accepted

- **Date:** 2026-08-26
- **Stage:** 8

## Context
During initial end-to-end testing, the agent successfully verified constraints but stalled because it could not explore the project directory or create new files. A greenfield specification cannot be implemented using only `fs_read` and `fs_apply_patch`.

## Decision
We will add two new tools to the MCP server, both strictly enforced by the `Sandbox` primitive introduced in ADR-001.

1. **`fs_list(directory_path: str = ".")`**: 
   - Returns a structured list of files and directories within the specified path.
   - Must prevent path traversal.
   - Must automatically exclude heavy/irrelevant internal directories (e.g., `.git`, `.venv`, `__pycache__`, `node_modules`, `.agent-harness`) to prevent LLM context bloat.
2. **`fs_write(filepath: str, content: str)`**: 
   - Creates a new file or overwrites an existing one with the provided content.
   - Must prevent path traversal.
   - Must automatically create parent directories if they do not exist.

## Implementation notes
- Both tools live in `mcp_server/tools/fs_tools.py` next to the existing file tools and
  resolve every path through `Sandbox.resolve()` (rejects absolute paths, `..`, symlink
  escapes). No change to `mcp_server/main.py` was needed: it registers whatever
  `mcp_server.tools.build_all_tools()` returns, so adding the two `ToolSpec`s to
  `fs_tools.build_tools()` is the registration.
- `fs_list(directory_path=".", recursive=False)` returns JSON
  `{directory, entries:[{path, type, size?}], truncated}`; entries are sorted directories
  first, then by name; `type` is `dir` | `file` | `symlink` | `other`. Excluded names
  (`EXCLUDED_DIRS`: `.git`, `.hg`, `.svn`, `.venv`, `venv`, `__pycache__`, `.pytest_cache`,
  `.mypy_cache`, `.ruff_cache`, `node_modules`, `dist`, `build`, `.agent-harness`,
  `.idea`, `.vscode`) are skipped at every depth. `recursive=True` walks the tree with the
  same exclusions; output is capped at `MAX_LIST_ENTRIES = 2000` and flags `truncated`.
- `fs_write(filepath, content)` calls `parent.mkdir(parents=True, exist_ok=True)`, refuses
  to overwrite a directory or write into an excluded directory, rejects content larger than
  `MAX_WRITE_BYTES = 1 MiB`, and reuses `_write_atomic()` (temp file + `os.replace`) so a
  crash never leaves a half-written file. The result string reports `created` vs
  `overwritten` and the byte count.
- `config/roles.yaml` and the persona tool list generated by `bin/run_agent.sh` now include
  both tools; the workflow step "explore with `fs_list` before reading" is added so the
  model no longer guesses filenames.

## Alternatives considered
- **Extend `fs_apply_patch` with an "empty search string creates the file" mode** — hides a
  destructive create/overwrite behind an edit tool's contract; explicit `fs_write` is clearer
  to the model and to reviewers.
- **`fs_list` returning a `tree`-style string** — cheaper in tokens but harder for the model
  to reason over reliably; JSON with explicit `type` fields is the structured output the ADR asks for.
- **Honouring `.gitignore` in `fs_list`** — nice, but pulls in glob semantics and per-target
  behaviour; a fixed exclusion list is predictable and covers the context-bloat cases.

## Self-critique
- `fs_write` is the first tool that can create files anywhere inside the target, including
  under `tests/`; the harness does not implement the target's "tests locked" convention —
  that remains the persona's and the human reviewer's responsibility.
- Exclusions are by directory *name*, so a legitimately named source directory called
  `build/` would be hidden from the agent. Acceptable for now; make it configurable if it bites.
- `fs_list` still exposes file *names* of secrets (`.env`); reading them is what `fs_read`
  guards, and the target's constitution forbids it, but the listing itself is not filtered.
- Symlinks are listed but not followed in recursive mode, so a symlinked source tree is
  invisible to the agent.

## Consequences
- The agent can now discover the project layout and create the files a greenfield spec
  requires; the run-3 stall (guessing `package.json`, `app.py`) has a proper remedy.
- The tool surface grows to 9; `docs/SPECS.md` §5 is the reference.
- Overwrites are possible: the persona instructs `fs_read` before `fs_write` on an existing
  path, and `git` history in the target remains the safety net.
